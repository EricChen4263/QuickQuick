# AI 活动记录 · DeepL 配额状态码 456 接线

## 背景

`src-tauri/src/translate/providers.rs` 的 `map_deepl_http_status` 文档写着「供框架层在拿到
HTTP 状态码后调用」，但全仓**零调用点**——`scripts/rust-dead-code-inventory.mjs` 把它列为
190 项候选里唯一一个「零引用」的真孤儿。DeepL 的配额超限返回**非标准** HTTP 456，只有
状态码能分辨（响应体文案不保证稳定），而当时这条路径靠 `map_deepl_error_from_body`
匹配 body 里的 "QUOTA"/"456" 文案兜底。裁定是**接线**，不是删除。

## 实际缺陷（不只死代码）

生产链路上 HTTP 状态码只在一个地方出现：`ipc::translate::UreqExecutor` 拿到
`ureq::Error::Status(status, _response)` 后交给 `error::map_provider_error(status, None)`。
`456` 原先落进 `map_by_http_status` 的 `_ => ServerError` 兜底，而 `retry::is_transient`
把 `ServerError` 判为**瞬时**失败——于是 DeepL 配额耗尽会被退避重试满 3 次
（`TRANSLATE_MAX_ATTEMPTS = 3`，退避 500/1000/2000ms，且同步命令阻塞主线程）。

即：**配额是持续性失败，重试只会把一次失败放大成三次请求**。接线同时修掉这点。

## 改动

1. `translate/providers.rs`
   - 新增 `pub const DEEPL_QUOTA_EXCEEDED_STATUS: u16 = 456`，作为「DeepL 私有状态码」
     的唯一来源，供通用归一层路由使用。
   - `map_deepl_http_status` 改用该常量；`body` 为空时文案只保留状态码
     （框架层只有状态码、没有 body，原实现会留下尾巴空格）。
2. `translate/error.rs`
   - `map_by_http_status` 增加 `providers::DEEPL_QUOTA_EXCEEDED_STATUS` 分支，把 456
     **路由**给 `providers::map_deepl_http_status`，产出 `Quota`。语义与文案仍归 DeepL
     provider 持有，通用表不掺 provider 专属词汇。

### 为什么路由点在 `error.rs` 而不是 provider 内部

`HttpExecutor::execute` 的契约是 `Result<String, TranslateError>`——非 2xx 在 ipc 的
`normalize_ureq_error` 里就被折叠成 `TranslateError`，**状态码与响应体都不再传给
provider**，`parse_response` 永远看不到 456。因此 provider 内部拿不到状态码，唯一的
生产可达接收点就是 `map_provider_error`。给 `HttpExecutor` 加带默认实现的状态码方法
只会是「看着接线、实际拿不到状态码」的假接线（默认实现无法凭空得到 status），故未采用。

真正的根治方向（后续项，需动 `ipc/*`、本次硬约束不允许）：让执行器返回
`(status, body)` 或让错误携带 status，把映射权彻底交回 provider。

## 测试（5 条新增，均在 `translate/`）

- `error::tests::http_status_normalization_through_production_executor`：本地回环起一个只回
  一行状态行的 HTTP 服务，**走真实 `UreqExecutor`**（生产执行器，不是假 executor）断言
  `456 → quota`、`403 → auth`、`429 → rate_limit`、`503 → server_error`。
- `error::tests::deepl_quota_456_is_not_retried`：用 `retry::retry_with_backoff` 实跑
  `max_attempts=3`，断言 456 只尝试 **1** 次、零退避等待。
- `error::tests::transient_server_error_is_retried_with_backoff`：**正向对照**——503 必须
  仍能重试满 3 次、退避序列 `[500, 1000, 2000]`。没有它，「只试 1 次」可能只是因为重试
  机制整体失效而恒真。
- `providers::tests::deepl_http_status_maps_quota_code_and_standard_codes` / 
  `deepl_http_status_message_without_body_has_no_trailing_space`：锁定 DeepL 状态码表
  各分支与空 body 文案。

## 变异验证（实做）

把 `map_by_http_status` 里的 456 路由分支删掉（其余不动）后重跑 `cargo test translate::error::`：

```
test translate::error::tests::deepl_quota_456_is_not_retried ... FAILED
  456 应归一为 Quota，实际：Err(ServerError("未知错误: HTTP 456"))
test translate::error::tests::http_status_normalization_through_production_executor ... FAILED
  HTTP 456 Quota Exceeded 的归一结果不符: 服务端错误: 未知错误: HTTP 456
  left: "server_error" right: "quota"
test result: FAILED. 1 passed; 2 failed
```

恢复接线后同一命令 3 passed / 0 failed。另：变异时 `use super::{providers, ...}`
变成未使用导入并报 `unused_imports` 警告（`clippy -D warnings` 也会红），属次要信号，
主信号是上面两条行为断言。
