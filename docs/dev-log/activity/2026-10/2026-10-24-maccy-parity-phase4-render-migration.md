# AI 活动记录 · 列表增量渲染 + 迁移框架版本化

## 摘要

- **P4-2a 列表增量渲染**：DOM 节点数从「全量」改成「首屏 100 条 + 滚到底部按块追加」，250 条时整页节点 3066 → 1266。
- **P4-7 schema 迁移框架版本化**：`PRAGMA user_version` + 有序迁移步骤 + 单事务回滚，把 ad-hoc 的「探测列是否存在再 ALTER」收编成正式步骤。

## 三件「明确不做」，都有理由

**1. 不做 DB 分页。** 搜索/类型筛选是在内存里对全量做匹配；只给 DB 加分页会让搜索只能命中「已加载的那一段」，这是正确性回归而不是性能问题。要做得先有 P4-5 的两段式加载（轻量索引全量 + 可见行取正文）。

**2. 不做固定行高窗口化。** `.clip-text` 是两行截断，行高在 41/54/60px 之间变化。固定行高虚拟滚动必须假定等高 → 只能强制固定高度 → 改视觉，这是不可接受的设计回归。所以窗口只能是「前缀 0..renderedCount」，选中项越窗时按块扩窗。

**3. 不用 `content-visibility: auto`。** 执行者加了它并主动标注了风险：它会让**离屏行退出无障碍树**。这个应用是纯键盘驱动的剪贴板管理器，VoiceOver 用户逐项浏览时「中间有 100 行摸不到」是很难被发现、也很难原谅的回归；而它的收益只是在**已渲染的 100 行**里跳过离屏行的布局绘制。撤掉后重测：**节点数逐位不变（1266）**——证明收益 100% 来自 slice。这条我作为 Lead 直接拍板撤除，并要求在 CSS 里留注释说明「为什么刻意不用」，否则后来人会顺手加回来。

## 一次「测试看着对但拦不住退化」

审查者做变异时发现：把 `filterKey` 从「类型筛选 + 搜索词」退化成按 `filteredItems.length` 判定，**全量 705 个测试 0 红**。也就是「搜索 A → 搜索 B 且两边命中条数相同」时不重置窗口。

补测试时还踩到一个构造上的坑：直接「特殊(3 条) → 普通(3 条)」切换**测不出**——第一次搜索已经因为长度变化（250→3）把窗口重置成 3，切换时窗口本来就小，退化实现照样绿。正确构造是「两边都命中 120 条、且切换前先把窗口撑到 120」再切。

这类缺陷的判据可以写成一句可复用的：**只要出现「X 变了所以作废 Y」，先问 X 是源条件还是派生量**；配套必须有一条「两个不同源条件产生相同派生值」的用例，否则该路径永假绿。

## 迁移框架：两条不可退让的设计

**1. `create_tables` / `ensure_indexes` 冻结为 v1 基线快照**，不再每次开库跑。
理由：版本号必须是「库是什么形态」的唯一真相。若把 `IF NOT EXISTS` DDL 留在开库路径上，未来往那里加列就会**绕过版本号**在用户开库时生效——同一个 `user_version` 下长出两种表形态，后续迁移步骤的前提立刻失效。代价是「外力删掉表/索引后不再自动补回」，刻意接受。

**2. 迁移错误不复用 `DbError::Sqlite`。**
因为 `open_or_recover` 会把 `Sqlite` 当「库已损坏」去改名备份——那样一次「旧程序打开新库」就会把完好的库搬走。新增 `SchemaTooNew` / `MigrationFailed` 两个变体，归 Permanent。

## 「诚实不能只存在于用户看不到的地方」

第一版只改了日志文案，`with_db` 仍说「原因见启动诊断日志」。但这是 GUI 应用，**打包后用户根本看不到 stderr**。所以又做了一步：`AppDb` 携带 `open_error`（`DbError::Display` 的原文），`with_db` 把原因拼进给前端的文案。

实际效果：
```
数据库不可用：数据库由更新版本的 QuickQuick 创建（v2 > v1），请更新应用后再试
数据库不可用：数据库升级失败（0→1）：no such column: title。原库未被修改，请联系支持
```

一处刻意的省略：**有原因时不再追加「若仍然失败请联系支持」**——两句原因本身已各带行动指引，追加会出现两遍「请联系支持」。兜底文案（无原因）才保留完整指引。

## 一条登记的风险，不是死代码那么简单

`db::open_or_recover` 生产 0 调用点（只有 4 处测试调用），而且它与生产 `reset_and_reopen` **判据分裂**：一个认 `DbError::Sqlite`，一个认 `is_resettable_open_error` 的字符串标记。未来若有人把它接进启动路径，会**静默改变恢复策略**（例如把 schema 错误当损坏备份掉）。

它是 `pub fn` + `pub mod`，`dead_code` lint 与 cargo-udeps 都发现不了——这意味着 P6-3 现有的工具对这类「公开但没人用」的函数是瞎的。
