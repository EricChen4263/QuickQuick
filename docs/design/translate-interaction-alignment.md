## 0. 结论

翻译按三层分别对齐，不选单一软件：

| 层 | 对齐对象 | 怎么用 | 许可约束 |
|---|---|---|---|
| 交互与窗口形态（热键即译、光标旁浮窗、即用即走） | **Bob** | 只参考交互，不参考代码 | Bob 不是开源软件（其 README 明确写明），**不得查看或引用其实现代码** |
| 翻译源清单 | **pot** | 作为「应支持哪些源」的功能清单（已完成，见 `translation-sources-pot.md`） | pot 为 GPL-3.0，不复制代码，不近似改写 |
| 词典结果视图（fast-follow） | **Easydict** | 参考「词典优先、音标/释义/例句」的信息层级 | Easydict 为 GPL-3.0，不复制代码 |

一句话：**交互学 Bob，源学 pot，词典学 Easydict，代码全部原创。**

## 1. 现状与差距

现状（已读代码确认）：

- 翻译浮窗 `trans-popover` 读的是**剪贴板历史最新一条**（`src-tauri/src/popover.rs` 调用 `pick_latest_translate_text_impl`），不是用户当前选中的文字。
- 没有任何取选中文字的实现（全仓无 `AXSelectedText` 调用）。
- 没有选中即出的图标，没有光标旁定位。

目标（`STRATEGY.md` G2 signal 与设计文档 §4.3）：

- 选中 → 光标旁冒小图标 → 用户点击或按 `Cmd+Shift+T` → 展开轻量浮窗。
- 浮窗瞥一眼即走，点别处消失。

| 维度 | 现状 | 目标 | 差距 |
|---|---|---|---|
| 取文本来源 | 剪贴板最新一条 | 当前选中文字（失败再降级剪贴板） | **大**：无取词通道 |
| 触发 | 热键 | 热键 + 选中图标 | 中：图标需要全局选中监听 |
| 定位 | 固定位置 | 光标 / 鼠标旁 | 中：需要 caret 或鼠标坐标 |
| 译文操作 | 复制 / 朗读 / 展开 | 同左 | 无 |
| 翻译源 | 21 源 + LLM | 同左 | 无 |

REMAINING-TODO §二.6 记录的「v1 主动降级（不做 AX、不模拟 Cmd+C）」是当时的取舍，代价是用户要先 Cmd+C 再按热键，和 Bob 的体验差距最大。本方案就是要把它补回来。

## 2. 方案分期

### P0 · 取词通道（热键即译取当前选中文字）

- macOS：通过 Accessibility 读取焦点元素的 `AXSelectedText`。
- 失败（未授权、应用不支持 AX、无选中）时的降级：
  - 未授权：复用已有的辅助功能引导卡片（`onboarding` 链路），不崩、不硬卡用户（`STRATEGY.md` 约束）。
  - 无选中或不支持：回退读取剪贴板最新一条，并在浮窗内如实标注「来自剪贴板」。
- Windows：**本期不实现取词**，沿用剪贴板降级，并标注「Windows 暂不支持选中取词」。（见 D1）
- 不模拟 Cmd+C（会污染剪贴板，与 REMAINING-TODO 既定决策一致；见 D3）。

验收：

- 在 Safari、Notes、TextEdit、Terminal 中选中文字按 `Cmd+Shift+T`，浮窗译的是选中文字而不是剪贴板内容。
- 撤销辅助功能授权后，浮窗给出明确降级提示，应用不崩溃。
- 选中为空时，浮窗给出「请先选中文字」提示，不误译剪贴板。

### P1 · 光标旁定位

- 浮窗定位优先取 AX 的选区边界（caret 矩形）；取不到时用鼠标坐标。
- 复用 `window_pos.rs` 的定位逻辑，按屏幕边界夹紧。
- 不抢焦点：沿用非激活 NSPanel 的经验（`docs/design/clip-popover-nspanel.md`）。

验收：

- 浮窗出现在选区附近，不遮挡选中文字，跨多屏时出现在当前屏。
- 浮窗不抢走原应用的键盘焦点（原应用的光标与选区不变）。

### P2 · 选中图标（已取消）

> 2026-10-31：实现后真机测试图标未出现，用户确认不需要（选中后按热键即可），已撤销（`91524cf`）。以下为原方案记录，保留作为历史。

- 需要全局选中监听（鼠标抬起 + AX 选区变化轮询）。
- 风险较高：CPU 占用、误触、隐私观感。**默认关闭**，由设置开关「选中文字时显示翻译图标」开启。
- 设计纪律保持不变：图标只出现，**绝不自动翻译**（设计文档 §4.3，`select-trigger.ts` 已有对应测试）。
- 实现要点（2026-10-31，用户指示「做完所有功能后再验证」）：
  - 全局 `LeftMouseUp` 触发一次后台取词（延迟 120ms 等应用同步选区）；`LeftMouseDown` 作废旧结果并收起图标。用代数（generation）丢弃过期取词结果。
  - 图标锚点取光标位置，不用 AX 选区边界，避免选区坐标与光标坐标单位混用。
  - 图标是非激活 NSPanel，`can_become_key_window=false`，出现与点击都不抢源应用焦点。
  - 点击图标复用冒图标时的同一份快照，不重新取词，经 `trigger_translate_prepared` 进入与热键相同的唤起链路。
  - 选中文字不写日志、不进剪贴板。
- 与 D2 的关系：D2 原定「P0/P1 真机后再决定」。用户已明确改为先做完全部功能再统一验证，故 P2 在真机前实现，真机结果仍可能导致关闭或回退该开关。

### P3 · 固定面板（剪贴板 / 历史 / 手输）

- 设计文档 §4.3 已定：剪贴板 / 历史条目 / 手输 → 固定面板，原文与译文上下对照。
- 现有翻译页与「一键翻译」基本覆盖，本期只补齐「浮窗展开 → 固定面板」的跳转参数，不新增界面。

### P4 · 词典结果视图（fast-follow，已实现）

- 单词查询时展示音标、词性、释义、例句。
- 数据层已就绪（ECDICT、有道词典）。浮窗对 `kind: "dict"` 结果复用主窗的 `DictEntryView`，不另起界面；浮窗样式在 `popover.css` 中以 `.mini-translate` 为作用域补齐一份（浮窗入口不加载主窗的 `translate.css`）。参考 Easydict 的信息层级，不复制其界面代码。
- 已知限制：浮窗高度 200px 对词典视图偏紧，需要滚动；是否按词典结果加高待真机观感决定（TP4-M01）。

## 3. 明确不做

- 不做选中即自动弹出翻译（设计纪律，避免高频选字时乱弹、烧额度）。
- 不做截图翻译、OCR（Bob 有，但不在 QuickQuick 的 STRATEGY 范围内）。
- 不做 PopClip 集成（可作后续项，本期不排）。
- 不做 AppleScript / 插件系统（pot 有 `.potext`，设计文档已排除）。
- 不因交互对齐而改动翻译源的非官方降级策略（`STRATEGY.md`：永不静默切换非官方源）。

## 4. 风险

| 风险 | 说明 | 应对 |
|---|---|---|
| AX 支持不一致 | Chrome 网页内容、Electron 应用默认不暴露 AX 选区，需要额外开启 | 验收清单覆盖 Chrome / Electron；失败走剪贴板降级并标注 |
| 辅助功能授权 | 每次自动更新后签名变化，需要重新授权（README 已有说明） | 复用既有引导卡片；不把授权当前提 |
| 剪贴板降级的误导 | 用户以为译的是选中文字，实际是剪贴板内容 | 浮窗必须显示来源标签（「选中」/「剪贴板」） |
| 非激活面板焦点 | 浮窗若抢焦点，原应用选区会丢失 | 沿用 NSPanel 方案；P1 验收项专门检查 |
| Windows 取词空白 | UIA TextPattern 未做调研 | 本期不承诺，单列调研项 |

## 5. 决策记录（2026-10-31 已确认）

- **D1 · Windows 本期不做取词**：走剪贴板降级，并标注「Windows 暂不支持选中取词」。
- **D2 · 选中图标（P2）暂缓**：P0/P1 真机验证后再决定是否启动。
- **D3 · 不模拟 Cmd+C**：降级只读剪贴板，不污染用户剪贴板。
- **D4 · 浮窗显示来源标签**：「选中」或「剪贴板」，避免误译认知。

**口径澄清（P0 实施时发现的内部冲突，按以下执行）**：§2 P0 验收里「选中为空时提示请先选中文字、不误译剪贴板」与 D3/D4 及 §2 P0 降级条「回退读取剪贴板并标注来源」互相矛盾。最终按后者执行：选中为空或取词不可用时，回退读取剪贴板最新一条，并用来源标签（「选中」/「剪贴板」）和降级原因提示如实告知用户。理由：Chrome 与 Electron 常读不到 AX 选区，若严格不回退，这些场景热键会整体失效；来源标签已经消解误译认知。空态（剪贴板也为空）的文案为「请先选中或复制文字再按 ⌘⇧T」。

实现约束补充（P0 实施时发现，已确认）：

- 取词必须在唤起 trans-popover **之前**完成。`trans-popover` 唤起时会激活 QuickQuick，焦点离开源应用后再读就拿不到选区。
- AX 调用需设置消息超时，避免目标应用无响应时阻塞热键回调线程。
- 热键回调只响应按下（`ShortcutState::Pressed`），忽略松开。插件对按下与松开各调用一次回调；不过滤的话，松开事件会在第一次触发已激活本进程之后再次取词，覆盖正确的选中快照。

**审查待办的处理结果（2026-10-31 已完成）**：
- 焦点应用是本进程时跳过取词：先经 `AXFocusedApplication` 取焦点应用，用 `AXUIElementGetPid` 比对本进程 pid，相同则直接放弃，不向本进程发 AX 请求（否则热键回调在主线程上等自己超时）。该分支依赖真实 AX 与前台状态，无法在单测中断言，见 TP0-M04。
- 来源快照清理：trans-popover 失焦隐藏时调用 `TransSourceStore::clear`，选中的文字不再在窗口关闭后留在内存里。挂载补读发生在用户看到窗口之前，不受影响。
