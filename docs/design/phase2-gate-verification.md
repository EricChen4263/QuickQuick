# Phase 2 门禁拆分与真机核对清单

- 日期：2026-10-24
- 目的：把「卡住无人值守推进」的人工验证从「整阶段 blocked」拆成「可探针化 / 已自动化覆盖 / 必须真人」三类，并给出可照做的真机核对步骤。
- 边界：本文只做拆分与清单，不改变既有决策。Phase 2 的**面板语义**结论仍需真人真机给出；本文只说明哪些条目不必等它。

---

## 一、为什么要拆

`docs/design/v04-work-items.md` 把整个 Phase 2 标为 blocked，理由是要先完成 ADR §6.2 的 8 项人工验证。但这个「整体 blocked」过粗，代价是：**一批与面板语义毫无关系的前端交互条目被一起冻结**。

两件事必须分开：

1. **面板语义是否成立**（面板不激活 app 也能收键盘、输入法正常、全屏可见）——这是架构前提，只能真人真机判定，**必须等**。
2. **面板内/窗口内的键盘与交互逻辑**（键位映射、数字直达、输入法 composition 期间不劫持、主窗 Enter 行为）——这些是 webview 层的纯逻辑，**与「窗口是不是 NSPanel」无关**。即使面板语义被证伪、回退成普通窗口路径，这些逻辑一行都不用改。

上一轮的实践也支持这个判断：P1-1 的 `NSPasteboard` 跨线程崩溃，本是「只有真机才知道」的隐患，最后是被**隔离探针**打成可复跑证据的（4/4 崩 vs 0 崩的对照）。所以「人工验证」里有一部分其实可以降级成自动化证据。

## 二、ADR §6.2 八项人工验证的重新分类

| # | 原验证项 | 新分类 | 说明 |
|---|---|---|---|
| 1 | 面板弹出不夺焦 | **可探针化（待做）** | 可用 Rust 侧探针：show 面板前后各取一次 `NSWorkspace.frontmostApplication().bundleIdentifier()` 与 `.processIdentifier()`，断言不变。需要真实 GUI 会话（有 WindowServer），但**不需要人手操作**——可在 `cargo test` 里跑，或作为 `--ignored` 的手动触发测试。注意：这类探针**必须自己创建自己的 NSWindow/NSPanel**，不能依赖 Tauri 启动流程。 |
| 2 | 中文输入法 composition 正常 | **必须人工** | 候选窗位置、上屏时序、首个字母是否丢失，是输入法进程与 AppKit 的交互结果，没有可编程观测量。**但**其中「composition 期间方向键是否被我们劫持」这一半已可自动化（P2-6 的单测覆盖），因为它是我们自己的逻辑。 |
| 3 | Enter 粘贴落到原应用 | **必须人工** | 「落到哪个应用」是系统行为；但「Enter 是否真的触发了粘贴调用」已可自动化（P2-7 组件测试）。 |
| 4 | Esc 关闭后原应用焦点完好 | **必须人工** | 焦点归属只能人眼/手感判定。 |
| 5 | 全屏 Space 下可唤起 | **必须人工** | 需要真人切 Space。ADR 已声明该行为照搬参考实现但本项目未独立验证。 |
| 6 | 面板失焦自动隐藏 | **可探针化（待做）** | 可程序化：让面板 becomeKey → 对另一个 app 发 activate 通知 → 断言面板 `isVisible == false`。同样需要 GUI 会话但不需要人手。 |
| 7 | 主窗口粘贴不回归 | **半自动** | 「是否注入 ⌘V」有单测（`should_inject_paste` 等）；「内容是否真的进到编辑器」必须人工。 |
| 8 | 辅助功能未授权时降级 | **半自动** | 降级决策路径有单测；真机需临时取消授权后验证，属人工但成本低（一次 TCC 开关）。 |

**结论**：8 项里 **2 项可探针化**（1、6）、**3 项有一半已被自动化覆盖**（2、3、7）、**3 项必须真人**（4、5、8）。可探针化的 2 项值得做——它们是「面板语义是否成立」里最关键的机械判据，做成探针对每次改动都能复跑，而不是每次靠人。

> 这两条探针本轮**没有做**（需要先确认它们能在本机 GUI 会话下稳定运行，且不应混进 Phase 2 的逻辑条目里）。作为后续候选。

## 三、Phase 2 work item 的依赖切分

| item | 依赖面板语义？ | 处置 |
|---|---|---|
| P2-2 键盘模型升级（⌃N/P/J/K、⌘↑↓、⌃W/U/H） | **否**（webview 键盘逻辑） | 可推进 |
| P2-3 数字直达 | **否** | 可推进 |
| P2-6 输入法防御 | **否**（`isComposing` / keyCode 229 判定） | 可推进 |
| P2-7 主窗键盘流修复 | **否**（主窗本来就不是面板） | 可推进（bug 级，优先） |
| P2-10 行内预览分级延迟 | **否** | 可推进（未开工） |
| P2-11 快捷键徽标随修饰键变 | **否** | 可推进（未开工） |
| P2-1 面板高度自适应 | **是**（面板尺寸/定位语义） | blocked |
| P2-4 字母 pin | 部分（需要 `pin` 列 + 迁移；持久化键位与面板无关，但「Pins 管理」入口在 popover） | 建议等 Phase 4 的迁移框架版本化一起做 |
| P2-5 cycle 模式 | **是**（全局 `flagsChanged` + 面板吞 ⌘V 语义） | blocked |
| P2-8 popover 管理动作（pin/删除/清空） | **是**（要在面板里操作且涉及后端 IPC 与刷新时序） | blocked（但纯后端 IPC 部分可先做） |
| P2-9 唤起位置可选 | 部分（窗口定位与是否面板无关，但多屏/全屏 Space 行为与面板耦合） | 建议等 §6.2 #5 结论 |

**执行口径**：只推进「依赖面板语义 = 否」的条目；一旦某条目在实现中发现必须触碰面板路径，立刻停止并转为 blocked，不得自行扩大范围。

## 四、Phase 1 遗留的四条人工项（可照做）

以下四条在 Phase 1 的交付里明确标为 pending-manual，逻辑链路均有单测/探针覆盖，缺的是真机端到端。

### 1. 敏感内容过滤（P1-1）

```bash
# 记录入库前的条目数
sqlite3 "$HOME/Library/Application Support/com.quickquick.app/quickquick.db" \
  "select count(*) from clip_items where is_deleted = 0;"
```
> 加密库（SQLCipher）无法用裸 sqlite3 打开；用 app 内「存储」页显示的条目数代替，或临时用 `-cmd "PRAGMA key=..."` 并自行取密钥（不推荐）。**推荐用 UI 条目数观察。**

步骤：1Password 里复制一个密码 → 打开 QuickQuick 主窗看历史列表 → 预期**不出现**该密码；再把设置页「跳过敏感内容」关掉 → 重复一次 → 预期**出现**。

### 2. 来源应用排除（P1-2）

设置页「隐私 → App 排除名单」加入 `1Password`（或 `TextEdit` 做对照）→ 在该 app 里复制一段普通文字 → 看历史列表 → 预期不出现；换一个不在名单里的 app 复制 → 预期出现。

注意命名语义：名单**同时匹配应用显示名与 bundle id**，大小写不敏感；身份取的是「最近一次被激活的外部应用」，若复制后立刻切走应用可能误判。

### 3. 自产标记（P1-3）

主窗里对某条历史点「复制」或按 Enter 粘贴 → 回到主窗看列表 → 预期**不新增条目**、原条目顺序不变。

### 4. 备份导出/导入（P1-5）

设置页「存储 → 备份/恢复」→ 输入口令 → 导出 → 预期显示落盘路径；点「在 Finder 中显示」→ 预期 Finder 弹出并选中该 `.qqbp`。
换一台机器（或临时改 `app_config_dir` 造一个空库）→ 「选择备份文件」→ 选该文件 → 输入口令 → 确认 → 预期条目被还原、顺序与源库一致；再用错误口令试一次 → 预期报「备份口令错误，或文件已损坏」且现有条目不变。

真机上还要留意：首次写 `~/Documents` 可能弹 macOS「访问文稿文件夹」授权；若被拒，导出应报明确错误而不是静默失败。

## 五、仍然只能由用户裁决的事

1. ADR §6.2 #2/#4/#5/#8 四项的真人结论（输入法、Esc 焦点、全屏 Space、未授权降级）。
2. 是否值得把 §6.2 #1/#6 做成常驻探针（本文建议做，但需要确认本机 GUI 会话下稳定）。
3. 数字直达的交互取舍：搜索框为空时按数字**立即粘贴**（Maccy 同款）vs 只高亮待 Enter。本轮回合按路线图「含 50ms 高亮反馈」实现为立即粘贴，若手感不对是一行改动。
